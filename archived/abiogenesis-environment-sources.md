# Abiogenesis — environment as sources, not fixed axes

Standalone design doc. Raised while scoping task 081 (proposal 1.E, "the
world breathes before the player seeds") — during that discussion the
1.E proposal itself shrank down to a much smaller scope (see task 081), and
this doc branched off to capture a larger, separate idea raised directly:
replace the current fixed-gradient environment model with source-driven
temperature and light. Same class of change as the terrain redesign (task
066-072) — touches worldgen and downstream balance, not just rendering — so
it gets its own doc and its own task split, kept out of 081.

## Current model (for reference)

`SimWorld::apply_environment_gradients` (`src/world.rs:413-429`), run once
at world creation, no RNG:

- **Temperature**: fixed linear gradient, left→right.
- **Light**: fixed linear gradient, top→bottom.

GDD §5.2's own comment on this code explains the intent: the two axes are
crossed on purpose so their combination creates a 2D niche space — a species
can occupy a spot defined independently by *both* its light and temperature
preference, not just one axis.

`SimWorld::diffuse_environment` (`src/world.rs:439-457`), run every tick
from `sim::step` unconditionally, all three scalars (temperature, light,
toxicity) included: a genuine Moore-neighbor blur toward the local mean at
`diffusion_rate` (default `0.05`/tick, `EnvironmentConfig`). There is no
pull back toward the original gradient — over a long run the fixed gradient
gradually erodes toward a flat field.

Downstream: `env_fit` (`src/sim.rs:392-395`, Gaussian around a species'
thermal optimum) reads `temperature`; `light` feeds `Photolithic` energy
gain directly (`sim.rs:252`). Both are load-bearing for the whole tick's
energy economy and for `DifficultyConfig`'s ramp
(`temperature_spread_late` and siblings).

## Why change it

The fixed-axis model is legible and easy to reason about, but it's also
uniform in a way that reads as static rather than alive — exactly the gap
1.E's diagnosis named ("the world has its own chemistry independent of the
player"). A source-driven model gives every world a distinct, readable
*shape* (where's hot, where's cold, which way light falls) instead of the
same two axes reskinned by different spread values every time, and ties
naturally into terrain data already generated by tasks 066-072.

**Decided in discussion**: the 2D-niche property (temperature and light as
independently combinable axes) is *not* preserved as a hard constraint —
niches are allowed to reshape around sources instead of two crossed lines.
GDD §5.2 will need rewriting to match, not just the implementation.

## Proposed model

### Temperature — point sources + wind bias, reinjected continuously

- At world creation, place *N* heat-source cells via a dedicated RNG stream,
  mirroring the established per-feature-offset pattern (`TERRAIN_SEED_OFFSET`,
  `TOXIC_ZONE_SEED_OFFSET` — `src/world.rs:255/354/528/533`): a new
  `TEMPERATURE_SOURCE_SEED_OFFSET`. `N` and each source's fixed temperature
  are `SimConfig` coefficients, plausibly ramped by difficulty like other
  worldgen params (`WorldParams`, `src/worldgen.rs`).
- Initial per-cell temperature derives from distance to the nearest source
  within a configurable radius, replacing the column-based `lerp`.
- A per-world wind direction (drawn from the same RNG stream) biases that
  distance anisotropically — closer effective distance downwind, farther
  upwind — reusing the *technique* task 069 used for multi-octave terrain
  waves, not its terrain-specific code.
- **Cooling**: `TerrainKind::Sea` cells (task 066, already generated) act as
  passive heat sinks — during `diffuse_environment`'s blend, a Sea cell's
  neighbors get pulled toward a low fixed value in addition to the normal
  Moore-mean, at a small configurable strength. Zero new random state: this
  reuses terrain data that already exists.
- **Reinjection**: without it, `diffuse_environment`'s existing blur erodes
  any source structure to flat over a long run, same problem the ambient
  residue trickle (task 060) solved for residue. Each tick, source cells are
  pulled back toward their fixed source temperature by a small strength
  before/after the normal blend — the source persists as a standing feature,
  not a one-time initial condition.

### Light — a per-world "sun" direction + mountain shadow

- Replace the fixed top-to-bottom `lerp` with a per-world sun angle (same
  RNG stream as temperature, or its own offset — decide during task
  scoping). Light per cell derives from a directional falloff (projection of
  the cell's position onto the sun direction), not a row index.
- **Shading**: `TerrainKind::Mountain`/peak cells (task 066, already
  generated) dim nearby cells during light computation — again, reusing
  existing terrain data instead of adding new state.
- Diffusion mechanism unchanged: light continues through the same
  `diffuse_environment` Moore-blur as temperature and toxicity.

### What stays untouched

- `diffuse_environment`'s Moore-blur mechanism itself (`world.rs:439-457`)
  — this doc changes what feeds it and what pulls against it, not the
  blur math. Its existing tests should keep passing unmodified.
- `env_fit` and the `Photolithic` light-gain formula (`sim.rs:392-395`,
  `sim.rs:252`) — this is a worldgen/generation change, not a tick-formula
  change. Species still read `temperature`/`light` the same way; only how
  those fields come to have their values changes.
- Toxic zone generation/placement (`world.rs:345-403`) — unrelated to this
  doc, no changes planned here.

## Open questions for task scoping

- How many heat sources per world, and does the count/placement ramp with
  `DifficultyConfig` like other worldgen parameters?
- Exact falloff function for distance-from-source (linear? inverse-square?
  smoothstep over a configured radius?) — needs a first pass and a visual
  playtest, not a number decided on paper.
- Whether wind bias and sun direction share one RNG draw (same world "mood")
  or are independent — affects whether hot/bright and cold/dark correlate
  spatially or not.
- Reinjection strength for sources/sinks: too strong and diffusion barely
  matters (back to static-looking); too weak and the source structure still
  erodes over a long run. Needs tuning against `diffusion_rate` (`0.05`),
  not chosen independently.
- `DifficultyConfig`/balance blast radius: `temperature_spread_late` and
  friends were tuned against the old lerp model — likely need rethinking
  entirely rather than reused as-is, since "spread" isn't a meaningful
  concept for a source-distance field the same way it was for a lerp.
- GDD §5.2 rewrite: the "two crossed axes create 2D niches" framing needs to
  become whatever the source model's actual niche geometry is — write this
  after the mechanics are implemented and playtested, not before, so it
  documents what's real.
