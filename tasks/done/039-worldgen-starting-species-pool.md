## 🎯 Objective

`seed_starting_palette` (`src/world.rs`, lines ~325-356) is an explicit placeholder from task 013: it always seeds 2 fixed photolithic species at the extremes of the thermal gradient, with a comment stating clearly *"Phase 3's procedural world generation replaces this with a real generator — do not extend this function, replace its call sites."*

This task replaces it with a real generator that, given the world generated by task 038 (active tags, matrix, environment), produces consistent starting species. It also introduces the distinction between an **available pool** (the superset of species the player could choose to seed, an attachment point for task 046's meta-progression) and species **actually pre-placed** in the world at the start of the run.

- [x] Tests: determinism, `TagConfig` constraints on placed species, correct placement on the grid, `available.len() > placed.len()` with at least one non-photolithic metabolism in the pool.

## Note on design: why only placed species are photolithic

The original criterion asked for "diversified metabolisms" without specifying whether the *placed* species should also vary. I chose to keep all species actually placed on the grid as `Photolithic` (the only metabolism self-sufficient from light alone, with no need for prey/detritus already present, GDD §5.4) and to introduce metabolism diversity only in the extra `available` pool (Predator/Decomposer, selectable by the player via `Seed` but not pre-placed). This avoids introducing pre-placed organisms with near-guaranteed death in the first ticks (an isolated predator with no prey dies in ~8 ticks per the GDD §5.9 formula), which would have risked systematically raising the extinction rate discovered by task 038. Empirically verified: the balance tests over 50 seeds stay within the already-set thresholds.

## 🧩 Technical Context

**Current `seed_starting_palette`** (`src/world.rs`, lines ~325-356): seeds 2 fixed photolithic species at the extremes of the thermal gradient. Placeholder from task 013, explicitly marked to be replaced (not extended) in Phase 3.

- **Current behavior**: every run starts with exactly the same 2 photolithic species, regardless of the generated world.
- **Desired behavior**: the starting species are generated from `world_seed`, consistent with that specific world's active tags/environment (task 038), with metabolism variety. There's a data shape that distinguishes "what the player could seed in this world" from "what starts already placed", ready to be extended by task 046's unlocks (which will add extra species to the available pool without touching this task's generation logic).

## 🔨 Suggested Implementation

1. Read `seed_starting_palette` and its call sites in `world.rs` in full before removing it.
2. Design a minimal type, e.g. `struct StartingPalette { available: Vec<Species>, placed: Vec<(Species, GridPos)> }` (indicative names, adapt to the existing code style) in `worldgen.rs`.
3. Write the generation: sample metabolisms/tags/positions from the world's RNG, respecting `TagConfig.tags_per_species_min/max` and consistency with the environment (e.g. temp_optimum distributed over the gradient generated by task 038, not fixed).
4. Replace `seed_starting_palette`'s call sites with the new generator.
5. Add the determinism and constraint tests.

## ⚠️ Constraints and Caveats

- **Determinism**: only `SimWorld`'s internal RNG, no dependency on clock/thread_rng.
- **Don't introduce unlock mechanics yet**: the available pool in this task is generated entirely by worldgen — the unlocks (task 046) will *extend* it later, this task only needs to leave room for that without a data-shape refactor.
- **Don't extend the existing placeholder**: replace the call sites, as indicated by the original comment — don't add conditional branches to `seed_starting_palette`.
- **No magic numbers outside `SimConfig`**: if new coefficients are needed (e.g. number of starting species), they go in `SimConfig`, not hardcoded in `worldgen.rs`.
