## 🎯 Objective

GDD §9: every procedurally generated world also includes its objective. This task connects worldgen (task 038, environment/tags) with the `Objective` type (task 040) to choose, given a `world_seed`, which objective to assign to a world and with what severity — growing with `WorldParams.objective_severity` (task 037).

---

## 📋 Acceptance Criteria

- [ ] Function in `src/worldgen.rs` that, given `world_seed`, `WorldParams`, and possibly the world generated by task 038/039 (active tags, environment, available species), chooses an `Objective` (task 040) variant and parametrizes its values (e.g. `min_species`, `ticks`, thresholds).
- [ ] The choice is deterministic from `world_seed` (same seed → same objective).
- [ ] Severity grows consistently with `world_index`/`WorldParams.objective_severity` (e.g. higher thresholds, longer required ticks in later worlds) — not an objective picked at random independently of difficulty.
- [ ] Minimal coherence check: the generated objective is not obviously unreachable given the environment/species generated for the same world (e.g. don't require survival in the toxic zone if the world has no toxic zone of non-zero size; don't require ≥N coexisting species if the pool of species available for that world is < N). A full reachability solver is not required — only a sanity check on the most obvious constraints.
- [ ] `cargo clippy -- -D warnings` clean, `cargo test` green.
- [ ] Tests: determinism, severity growth with `world_index`, absence of obviously incoherent objectives on the tested edge cases.

## 🧩 Technical Context

See task 040 for the `Objective` type and its variants (`Coexistence`, `SurviveIn`, `TriggerBloom`), and task 037 for `WorldParams.objective_severity`.

- **Current behavior**: no objective exists for any world — task 040 introduces the type and the evaluation engine but not the procedural generation.
- **Desired behavior**: every generated world has an assigned objective, consistent with its own environment/tags/species and with the severity expected for its `world_index`.

---

## 🔨 Suggested Implementation

1. Decide a simple selection strategy: e.g. sample an `Objective` variant from the world's RNG among those defined in task 040, then parametrize it by scaling the base values by `objective_severity`.
2. For the minimal coherence check, only verify the most direct constraints (e.g. if `SurviveIn { zone: Toxic, .. }` is chosen, verify that `WorldParams`/the generated environment actually has a toxic zone of non-zero area; if `Coexistence { min_species, .. }` is chosen, verify that `min_species` doesn't exceed the number of available species generated by task 039).
3. Integrate the call into the existing world-generation flow (where task 038 orchestrates tags/matrix/environment).

---

## ⚠️ Constraints and Caveats

- **Determinism**: only the world's internal RNG.
- **Not a full solver**: the reachability check is a sanity check on the most obvious constraints, not a formal proof that the objective is always solvable (the difficulty/unpredictability of emergence is part of the design, GDD §14).
- **Don't introduce bonus objectives**: explicitly out of the MVP (GDD §8: "planned in principle... but after the clean primary-objective→advance core. Not in the minimal MVP").
